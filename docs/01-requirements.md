# 01 · 需求与决策记录

本文记录「为什么是这个样子」。凡属用户拍板的结论，均注明日期与被否掉的选项及原因；凡属实现中的偏离，逐条记录。

---

## 一、项目定位

OpenMetroUI（`OM`）是一个 Android 原生 UI 库，视觉语言融合 **Metro 的动态磁贴** 与 **瑞士国际主义排版**。

一句话定义：**用瑞士的栅格与色彩纪律，约束 Metro 的色块与触感。**

它不追求「比 Material 更好用的组件集」，而是提供一套**有明确立场**的视觉系统：直角、无阴影、单强调色、4dp 网格、巨大 Light 标题、色块即内容。

---

## 二、目标与非目标

### （一）目标

1. 一套可执行的 Token 规范（色板、字阶、栅格、间距、形状、动效），数值确定、无歧义。
2. 一套从 foundation 自建的组件，**完全不继承 Material3**，不受其视觉与 API 影响。
3. 一个能当「活规范」用的 demo app：能在运行时调 token、能叠加网格、能看真实页面效果。
4. 可直接作为 Android 库被外部项目依赖（Gradle 多模块 + 可发布）。

### （二）非目标（明确不做）

| 不做 | 理由 |
|---|---|
| Material3 兼容层 / 主题互操作 | 会迫使视觉向 M3 妥协，违背立项前提 |
| XML View 体系的双实现 | 维护量翻倍，且 Compose 是唯一目标 |
| iOS / Desktop / Web 版本 | 先验证视觉语言在 Android 上成立，跨端留到 MAJOR |
| 打包字体文件 | 库体积与授权维护成本，改为宿主注入 |
| 全量图标库 | 只做 UI 必需的图标；`material-icons-extended` 明确不引入 |
| 动态取色作为默认 | 会摧毁「唯一强调色」纪律，只作为 opt-in |
| 阴影 / 毛玻璃 / 渐变等「现代感」装饰 | 与两条源流都冲突 |

## 三、需求拷问结论（2026-10-21）

### （一）技术栈：Compose + Foundation 自研

**拍板**：完全自建，不继承 Material3。

**被否选项与代价**：

| 选项 | 否决理由 |
|---|---|
| Compose + Material3 基底 | 上手快，但 M3 的 ripple、圆角、elevation、ColorScheme 语义会持续渗透；要做到「看不出 M3」的工作量并不低于自建，还多一层对抗 |
| Compose + View 双体系 | 覆盖老项目听起来划算，但 Metro 的磁贴翻转、reveal 揭示、自定义按压反馈都要写两遍，维护量翻倍 |
| Compose Multiplatform | 当前只需 Android；KMP 的 expect/actual 会拖慢每个组件的落地速度 |

**代价（已知并接受）**：基础组件（按钮、输入框、开关）全部要自写交互与无障碍语义，第一版组件数量会明显少于 M3 现成可得；`TextField` 的文本选择、`Dialog` 的窗口管理这类「脏活」需要额外投入。

**缓解**：代码层面不写 Android 专有 API（除必要的窗口与无障碍），为将来迁移 KMP 留余地。

### （二）视觉基调：先只做 Token 规范

**拍板**：第一阶段只交付 Token 规范，暂不定义组件。

**理由**：融合风格的成败全在「网格与色彩纪律」，这部分必须先钉死。先做组件会导致每个组件各自发明间距与颜色，最后收不回来。

**执行结果**：见 [00-design-language.md](00-design-language.md)。

### （三）第一阶段交付：先出规范文档，不写代码

**拍板**：文档先行，确认后再实现。

**代价**：在看到真实界面之前，字号 64sp、磁贴尺寸、对比度这些判断只能靠数值推理。**风险点**：`display.xl = 64sp` 与 `tile.solid` 系列在白字对比度上的实际观感，需要 demo app 跑起来才能最终确认。这两项标记为「实现后必须回看」。

### （四）交付形态：Gradle 工程 + demo app

**拍板**：`library module + sample app`，Gradle 多模块，demo app 必须存在。

**被否选项**：「单 app 先当 demo，稳定后抽库」——否决理由是抽库时包名、资源前缀、依赖边界都要重做，且 demo 里容易直接引用内部实现，抽离时才发现 API 不成立。

**Maven Central 发布**：本阶段不做，但模块结构（groupId / artifactId / 可发布的独立模块）按可发布标准设计，避免后期返工。

## 四、视觉立场的关键裁决

以下五条是本项目的「宪法」，详细数值见 [00-design-language.md](00-design-language.md#一设计立场)：

1. **零圆角**。矩形元素圆角恒 0；只有语义上本就为圆的元素（头像、状态点、单选、进度环）例外。
2. **零阴影**。层级只能由色块明度与字号建立。
3. **单色相**。全局一个 accent；多色磁贴为 opt-in 且等明度、只变色相。
4. **网格唯一**。一切尺寸是 4dp 的整数倍，文字基线落在网格上。
5. **动效白名单**。只允许位移、淡入、色块揭示、磁贴翻转、颜色过渡；禁止弹簧与回弹。

**被否掉的融合方案**：「Metro 主导 + 瑞士只做字体」——否决理由是这样出来的是「Windows Phone 换了个字」，瑞士风格沦为装饰；反过来「瑞士主导 + 色块当点缀」则失去磁贴作为导航结构的价值。当前方案是让两者各自负责自己最强的部分：**瑞士管结构，Metro 管块面与触感**。

## 五、协作规则

沿用既有习惯，本项目继续执行：

1. **需求先追问**：把选项与代价摆出来再动手，不自行假设。
2. **AI 不主动测试**：只保证编译通过（零错误零告警），真机验证由用户执行；用户明确说「测试」时才做设备验证。
3. **偏离必须声明**：实现与文档不一致时逐条说明理由与代价，并回写本文。
4. **文档与代码同步**：改了 token 数值就改 00，改了结构就改 02，不留过期描述。
5. **版本号**：`v0.MINOR.PATCH`；新需求进 MINOR，缺陷与小调整按**条数**进 PATCH，纯文档与构建脚本不占版本位。

## 六、边界与已知限制

| 限制 | 说明 |
|---|---|
| 字体 | 库不打包字体。默认跟随系统（Roboto / 系统中文），最佳效果需宿主注入 Inter + 思源黑体 |
| 字号适配 | 三条不变量会限制组件形态：不提供写死高度的组件，Material 式固定高度 AppBar 不可用 |
| 磁贴尺寸 | 磁贴按栏跨度的整数倍布局，无法做自由像素尺寸（这是设计约束，不是缺陷） |
| 动效 | 不做弹簧动画，交互手感会偏「硬」。这是风格选择 |
| 发布 | 本阶段仅本地依赖，未配置签名与 Central 发布 |
| 主题 | 不支持 M3 的 `ColorScheme` 语义，宿主若混用 M3 组件会出现两套视觉并存 |

## 八、实现偏离记录

### （一）v0.1.0（2026-10-21）

| # | 原方案 | 实际做法 | 理由 | 代价 |
|---|---|---|---|---|
| 1 | Paper `neutral.500` = `#8E8E88` | 改为 `#85857F` | 对 `surfaceVariant` 只有 2.94:1，不到控件边界的 3:1 | 中性阶整体略深，纸感稍减 |
| 2 | Ink `neutral.600` = `#7A7A74` | 改为 `#90908A` | 对 `surfaceVariant` 只有 3.92:1，不到次要文本的 4.5:1 | 深色下次要文本更亮，与主文本的层级差变小 |
| 3 | 语义表只有 `line` / `lineStrong` | 增加 `fieldLine` | `line` 是装饰性分隔线（1.16:1），不能承担「控件边界」的 3:1 要求 | 多一个语义 token，含义更精确 |
| 4 | `accentQuiet` 写死 `#FBEAE7` / `#3A1210` | 由 accent 以 10% / 18% 叠加推导 | 宿主替换 accent 时写死值会串色 | 实际值与文档原值有 1–2 的色差 |
| 5 | 只校验 accent 对比度，不修正 | 过浅/过暗的 accent 自动向黑或白混合到 3:1 | 宿主传浅黄会得到看不见的焦点环；「校验后报错」对使用方更不友好 | 极端色相会被改变，不再是宿主给的准确颜色 |
| 6 | 库不导出 Compose BOM | `api(platform(compose-bom))` | 组件签名暴露 `Dp` / `Color` / `TextStyle`，使用方必须与库同一套 Compose 版本 | 使用方被约束在 BOM 版本上 |
| 7 | 「所有尺寸是 4dp 的整数倍」 | 描边宽度 1 / 2 / 3dp 作为例外写入规范 | 描边是视觉重量，不是布局尺寸；强行取 4dp 会让结构线过重 | 规范多一条例外 |
| 8 | 未规定 system bar 处理 | demo 用 `enableEdgeToEdge` + 手动切换 `SystemBarStyle` | 手动切主题时状态栏图标必须跟着变，否则 Ink 下看不见 | demo 多一段平台相关代码（库本身不涉及） |

| # | 原方案 | 实际做法 | 理由 | 代价 |
