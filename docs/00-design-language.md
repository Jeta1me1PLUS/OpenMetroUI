# 00 · 设计语言与 Token 规范

本文是 OpenMetroUI 的**唯一视觉真源**。任何组件实现、任何视觉争议，都以本文的数值与裁决为准。本文只定义 token 与规则，不含代码；token 到 Compose API 的映射见 [02-architecture.md](02-architecture.md#三token-层设计)。

---

## 一、设计立场

### （一）两条源流

| 源流 | 提供什么 | 不采用什么 |
|---|---|---|
| **Metro**（Windows Phone / Zune） | 色块即内容、磁贴即导航、全出血横滑、巨大 Light 字重标题、无 chrome 的直角块面、翻转揭示、单一 accent | 高饱和多色拼贴、装饰性翻转动效、磁贴自由浮动 |
| **瑞士国际主义**（苏黎世 / 巴塞尔） | 数学栅格与基线、flush-left 对齐、极端字号跨度、留白作为结构、中性无衬线、单一强调色、客观无装饰 | 印刷独有的油墨叠印与专色、海报级的大面积图底反白（在屏幕上改为可选） |

两者的交集是：**扁平、无衬线、网格、字号建层级、拒绝装饰**。两者的分歧是本次设计的核心难题，交由下表的裁决规则解决。

### （二）四条硬约束

这四条不可协商，任何组件违反即视为设计缺陷：

1. **零圆角** —— 矩形元素圆角恒为 `0dp`。唯一允许的「圆」是语义上本就为圆的元素：头像、状态点、进度环、单选按钮。
2. **零阴影** —— `elevation` 恒为 `0dp`。层级只能由**色块明度差**与**字号差**建立，不能用投影、不能用模糊、不能用渐变。
3. **单色相** —— 全局只允许一个强调色相。彩色磁贴是 opt-in 模式，且必须等明度、等彩度，只变色相。
4. **网格唯一** —— 所有尺寸是 4dp 的整数倍，所有文字基线落在 4dp 网格上。不存在「凭感觉的间距」。

### （三）源流冲突的裁决表

融合风格最容易死在「两边都想要」。以下逐项裁决，并在实现中执行：

| 冲突项 | Metro 主张 | 瑞士主张 | 裁决 | 理由 |
|---|---|---|---|---|
| 圆角 | 直角（WP7/8） | 直角 | **直角** | 一致项，作为风格标识强化 |
| 阴影 | 无 | 无（印刷无投影） | **无** | 一致项 |
| 色彩数量 | 多彩磁贴 | 黑白 + 一色 | **默认单色相；多色为 opt-in 且等明度** | 保留 Metro 的色块节奏，但不许破坏瑞士的色彩纪律 |
| 标题字重 | Light / 超细 | Medium / Bold | **Display 段 300，UI 段 400，强调 600** | Metro 的轻盈感用于巨字，瑞士的坚实感用于可读文本 |
| 对齐 | 居中与左对齐混用 | 严格 flush-left | **严格 flush-left**（RTL 下为 flush-right） | 居中会破坏栏网格的可读性 |
| 动效量 | 多（翻转、飞入、透视） | 近乎静止 | **白名单制**：仅位移、淡入、色块揭示、磁贴翻转 | 动效只承担「状态迁移」的信息，不做表演 |
| 图标 | 简洁线性 | 几何线性 | **线性 1.5dp，方头端点、直角拐角** | 圆头端点会带回 Material 的柔和气质 |
| 按压缩放 | 磁贴轻微下沉 | 无 | **明度下沉，不做缩放** | 缩放会破坏块面的几何稳定感 |
| 留白 | 中等 | 大量 | **取瑞士值（偏大）** | 留白是这套语言的结构，不是余量 |
| 分隔线 | 弱化、常无 | 可见的细线 | **1dp hairline，仅在列表与表格中使用** | 有节制的可见线，替代阴影的层级功能 |

## 二、网格

### （一）基准单位

- 基准单位 `unit = 4dp`。
- 所有间距、高度、内边距、图标尺寸的取值必须是 `unit` 的整数倍。
- 文字行高必须是 `unit` 的整数倍，保证多列与并排文本的基线对齐。

### （二）间距阶

命名采用**倍率**，`space.n = n × 4dp`，只允许下表中的档位：

| Token | 值 | 用途 |
|---|---|---|
| `space.1` | 4dp | 图标与文字的间隙、描边偏移 |
| `space.2` | 8dp | 紧凑元素内部间距、标签与值 |
| `space.3` | 12dp | 控件内边距（小）、列表项内部 |
| `space.4` | 16dp | 控件内边距（默认）、段落间距 |
| `space.6` | 24dp | 区块内分组间距 |
| `space.8` | 32dp | 区块之间 |
| `space.12` | 48dp | 大区块之间、屏幕上下留白 |
| `space.16` | 64dp | 章节之间 |
| `space.24` | 96dp | 页面级留白、空状态 |

不允许出现 6dp、10dp、14dp、20dp、28dp 这类值。

### （三）栏网格

| 窗口宽度 | 类别 | 栏数 | 页边距 | 栏间距 |
|---|---|---|---|---|
| < 600dp | Compact | 4 | 16dp | 16dp |
| 600–839dp | Medium | 8 | 24dp | 16dp |
| 840–1199dp | Expanded | 12 | 32dp | 24dp |
| ≥ 1200dp | Large | 12 | 48dp | 24dp |

- 栏宽 = `(可用宽度 − 2 × 页边距 − (栏数 − 1) × 栏间距) / 栏数`，由布局运行时计算，不预设。
- 组件通过**跨栏数**定位（`span = 1..12`），不写死宽度。
- 允许「全出血」：磁贴、图片、分隔线可以跨越页边距延伸到屏幕边缘，但**内部文字仍须对齐到栏网格**。

### （四）文本行宽

- 正文单行字符数上限 **72 字符**（约 640dp）。超过即视为排版缺陷，必须收窄容器或改多栏。
- 大标题（display）允许单行跑满 4 栏，但不得超过 2 行；超出时降一级字号而不是换行三次。

### （五）系统栏与底色

这两件事由容器负责，组件不各自处理：

- **底色**：`OmTheme` 默认铺一层 `background`。深色主题下窗口底仍是浅色，不铺就会露出白边。局部嵌套主题传 `paintBackground = false`。
- **系统栏**：`OmScreen` 默认避开状态栏与导航栏。骨架外层已经统一处理过 insets 时传 `applyInsets = false`，否则双倍间距。

不用 `OmScreen` 的自定义骨架，这两件事要自己负责：外层 `background(colors.background)` + `statusBarsPadding()` / `navigationBarsPadding()`。

### （六）基线

- 组件垂直节奏以 `unit` 对齐；多列并排时文字基线必须对齐（用 `alignByBaseline` 语义实现）。
- 图片与色块的顶边或底边必须落在 `unit` 网格上，不允许「图片略高于文字」的视觉微调。

## 三、排版

### （一）字体策略

| 角色 | 首选 | 回退 |
|---|---|---|
| 拉丁文本 | Inter（SIL OFL，可变字体） | Roboto → `FontFamily.SansSerif` |
| 中文文本 | 思源黑体 / Noto Sans SC（OFL） | 系统 sans |
| 数字 | Inter 的 tabular figures（等宽数字） | 系统 sans 的 `tnum` |

- **库不打包字体文件**（每个字重数 MB，会让库变重且涉授权维护）。库提供两套预设：`OmTypography.System`（跟随系统字体）与 `OmTypography.Inter`（需宿主自行提供字体资源），以及完全自定义入口。
- 中文与拉丁混排时，字体族按列表回退；混排的字号与行高由同一套 token 决定。
- 数据、时间、计数、金额一律使用等宽数字，避免列表跳动。

### （二）字阶

字阶**不是等比模数**。UI 段采用约 1.2 的压缩阶梯，Display 段直接跃升 1.33 倍，用跨度而非均匀梯度制造层级——这是瑞士排版的做法。

| Token | 字号 | 行高 | 字重 | 字距 | 用途 |
|---|---|---|---|---|---|
| `display.xl` | 64sp | 68sp | 300 | −2.0sp | 磁贴主字、封面标题 |
| `display.l` | 48sp | 52sp | 300 | −1.5sp | 页面主标题 |
| `display.m` | 36sp | 40sp | 300 | −1.0sp | 区块大标题 |
| `headline` | 28sp | 32sp | 400 | −0.5sp | 卡片标题、对话框标题 |
| `title` | 22sp | 28sp | 600 | −0.25sp | 列表主文本、小标题 |
| `subtitle` | 18sp | 24sp | 400 | 0sp | 次级标题、强调正文 |
| `body.l` | 16sp | 24sp | 400 | 0.15sp | 正文（默认） |
| `body.m` | 14sp | 20sp | 400 | 0.25sp | 次要正文、说明 |
| `caption` | 12sp | 16sp | 400 | 0.4sp | 注释、时间戳 |
| `label` | 11sp | 16sp | 600 | 1.5sp | 全大写标签、字段名 |

规则：

1. **`label` 必须全大写**并使用 1.5sp 字距——小字靠开字距获得存在感，这是瑞士小字号招牌手法。
2. **字重只用三档**：300 / 400 / 600。不引入 500、700、800，避免层级靠粗细堆积。
3. **同一屏内最多 4 个层级**。出现第 5 个字号说明信息架构有问题，应合并。
4. **Display 段允许负字距**，UI 段不允许负于 −0.5sp。
5. 字阶之外不允许自定义字号；确需新档位时先改本表。

### （三）行高与段落

- 正文行高固定 `1.5 ×` 字号（16/24），不随内容调整。
- 段落间距 = `space.4`（16dp），段落内不缩进（flush-left，块状段落）。
- 列表项内多行文本行高仍为 1.5 倍，禁止压缩行高换取信息密度。

## 四、颜色

### （一）结构：无彩骨架 + 单色相强调

颜色系统分三层，**任何界面元素只能从这三层取色**：

1. **中性阶**（12 阶）—— 承担所有结构：背景、表面、文本、分隔线、禁用态。
2. **强调色**（accent）—— 唯一色相，承担：选中、焦点、进度、主要按钮、关键数据。
3. **磁贴色**（tile）—— 仅用于 `OmTile` 的色块；默认由中性阶与 accent 派生，opt-in 时启用八色组。

### （二）中性阶

刻意带极微量暖调（饱和度 < 2%），以区别于 Material 的冷灰，同时避免变成「复古纸张」：

| Token | 浅色（Paper） | 深色（Ink） |
|---|---|---|
| `neutral.0` | `#FFFFFF` | `#0C0C0B` |
| `neutral.50` | `#FAFAF8` | `#141413` |
| `neutral.100` | `#F2F2EF` | `#1C1C1A` |
| `neutral.200` | `#E4E4E0` | `#262624` |
| `neutral.300` | `#D0D0CB` | `#333330` |
| `neutral.400` | `#B3B3AD` | `#454541` |
| `neutral.500` | `#85857F` | `#5C5C57` |
| `neutral.600` | `#6B6B66` | `#90908A` |
| `neutral.700` | `#4C4C48` | `#9C9C96` |
| `neutral.800` | `#31312E` | `#C2C2BC` |
| `neutral.900` | `#1A1A18` | `#E4E4E0` |
| `neutral.1000` | `#0C0C0B` | `#FAFAF8` |

深色模式不是简单反相：中性阶在中段做了压缩调整，保证次要文本与控件边界在两套主题下都达标。其中两档是按实测对比度调整的（v0.1.0 落地时发现，原值差一点点）：

- Paper 的 `neutral.500` 由 `#8E8E88` 加深为 `#85857F` —— 原值对 `surfaceVariant` 只有 2.94:1，不到控件边界要求的 3:1。
- Ink 的 `neutral.600` 由 `#7A7A74` 提亮为 `#90908A` —— 原值对 `surfaceVariant` 只有 3.92:1，不到次要文本要求的 4.5:1。

这两处调整由单元测试发现，不是凭观感改的。

### （三）语义别名

组件只允许使用语义别名，不允许直接引用 `neutral.xxx`：

| 语义 Token | 浅色取值 | 深色取值 | 说明 |
|---|---|---|---|
| `background` | `neutral.50` | `neutral.0` | 页面底 |
| `surface` | `neutral.0` | `neutral.100` | 卡片、面板、浮层 |
| `surfaceVariant` | `neutral.100` | `neutral.200` | 次级面板、输入框底 |
| `textPrimary` | `neutral.1000` | `neutral.1000` | 主文本（两套主题都取反相端的极值） |
| `textSecondary` | `neutral.600` | `neutral.600` | 次要文本 |
| `textDisabled` | `neutral.400` | `neutral.500` | 禁用 |
| `line` | `neutral.200` | `neutral.300` | 1dp 分隔线（装饰性，不承担控件边界） |
| `lineStrong` | `neutral.800` | `neutral.700` | 2dp 结构线 |
| `fieldLine` | `neutral.500` | `neutral.600` | 输入框底线等必须可辨识的控件边界（≥3:1） |
| `accent` | `#DA291C` | `#FF5A4A` | 唯一强调色 |
| `onAccent` | `#FFFFFF` | `#0C0C0B` | accent 上的文字，由对比度算法选出 |
| `accentQuiet` | 推导 | 推导 | accent 以 10%（深色 18%）叠加在 `background` 上，不写死色值 |
| `inverseSurface` | `neutral.1000` | `neutral.50` | 反白块 |
| `onInverse` | `neutral.50` | `neutral.1000` | 反白块上的文字 |

表中两列写的是**中性阶 token 引用**，不是十六进制色值。中性阶在 Ink 主题下整体反转，因此 `neutral.0` 在 Ink 中即 `#0C0C0B`；部分别名（如 `surface`）在两套主题下刻意指向不同档位，以维持「表面比背景亮一级」的关系。

### （四）强调色

- 默认 `accent = #DA291C`（近似 Pantone 485，瑞士海报惯用红），白字对比度 **4.87:1**，满足 AA。
- 深色主题提亮为 `#FF5A4A`，对 `#0C0C0B` 对比度 **6.37:1**。
- 强调色可在主题层整体替换（`OmTheme(accent = …)`），但**一次只能有一个**。局部替换（如磁贴内）只允许通过 `OmAccentScope`，且必须同时提供 `onAccent`。
- `onAccent` 不需要宿主填写：由对比度算法在黑白之间选出更高者，因此永远 ≥ 3:1，常规 accent 下 ≥ 4.5:1。
- **过浅/过暗的 accent 会被自动拉回可辨识范围**：accent 要作为焦点环、指示条、进度使用，必须对**最不利的表面**（Paper 取 `surfaceVariant`、Ink 取 `surfaceVariant`）达到 3:1。达不到时逐级向黑（浅色主题）或白（深色主题）混合，取第一个达标值。这条规则保证宿主传任何色相都不会得到「看不见的强调色」，代价是极端色相会被改变。

### （五）状态色与「危险色」的裁决

这是单色相系统必须回答的问题：**强调色已经是红，危险提示怎么办？**

裁决：

- **危险态不引入新色相**。破坏性操作的按钮仍用 `accent` 填充，靠**实心警告图标 + 明确的动词文案**（「删除」「清空」）区分，而不是靠另一种红。
- 例外：破坏性操作的**确认按钮**允许使用 `danger = #A3150A`（比 accent 低 15% 明度，同族可辨），且只允许用于填充，不允许用于文字。
- `warning = #B26A00`、`success = #2E7D5B` 均已去饱和。**只允许出现在 ≤ 24dp 的图标、≤ 2 行的文字、2dp 的线条上**，禁止大面积填充。
- `info` 不设独立色，用 `accent`。

### （六）磁贴色

磁贴是 Metro 的灵魂，也是唯一被允许出现色块的地方。分两种模式：

**模式 A · Monochrome（默认）**

磁贴只使用中性阶与 accent 的明度变体，靠明度差形成节奏：

| Token | 浅色 | 深色 | 文字色 |
|---|---|---|---|
| `tile.paper` | `neutral.0` + 1dp `neutral.200` 描边 | `neutral.100` | `textPrimary` |
| `tile.quiet` | `neutral.100` | `neutral.200` | `textPrimary` |
| `tile.ink` | `neutral.1000` | `neutral.50` | `onInverse` |
| `tile.accent` | `accent` | `accent` | `onAccent` |

**模式 B · Spectrum（opt-in）**

八色，全部在 OKLCH 中固定明度与彩度、只变色相，因此不会「花」：

| Token | 色相 | Tint（浅底，配深字） | Solid（深底，配白字） |
|---|---|---|---|
| `tile.vermilion` | 25° | `#F6DDD7` | `#B33A2A` |
| `tile.ochre` | 60° | `#F3E7CB` | `#8A6A14` |
| `tile.olive` | 100° | `#E4E8D2` | `#5C6A2A` |
| `tile.teal` | 175° | `#D6E7E3` | `#26695F` |
| `tile.cobalt` | 255° | `#DCE3F3` | `#33518F` |
| `tile.slate` | 250° | `#E0E4E8` | `#4A5560` |
| `tile.plum` | 320° | `#EEDDE6` | `#6E3B5C` |
| `tile.crimson` | 5° | `#F7DBDD` | `#9C2E3A` |

约束：

1. 每个磁贴色必须成对提供 `(surface, onSurface)`，且对比度 ≥ 4.5:1。构建期有单元测试遍历全部色对，不达标即构建失败。
2. 一个磁贴网格内**最多同时出现 3 种色相**，且必须包含至少一个中性磁贴。八色不是用来铺满的。
3. Spectrum 模式默认关闭，由宿主显式开启；开启后 accent 仍只用于交互态，不参与磁贴着色。

### （七）明令禁止

- 渐变（含 linear / radial / sweep，进度条的硬边分段除外）
- 阴影与模糊（含 glassmorphism）
- 半透明色块叠加（alpha 只允许用于禁用态与 scrim，scrim 固定 `#000000` @ 32%）
- 动态取色（Material You）作为默认值；仅提供 opt-in，且只映射 accent，不映射中性阶
- 除 accent 与 Spectrum 八色之外的任何色相

## 五、形状与描边

| Token | 值 | 说明 |
|---|---|---|
| `shape.none` | 0dp | 组件默认圆角，全覆盖 |
| `shape.full` | 50% | 头像、状态点、单选、进度环 |

| Token | 值 | 用途 |
|---|---|---|
| `stroke.hairline` | 1dp | 分隔线、输入框底线（默认态）、卡片描边 |
| `stroke.emphasis` | 2dp | 输入框聚焦线、焦点环、选中指示 |
| `stroke.accent` | 3dp | Pivot 指示条、底部导航选中条 |

- 描边**内缩绘制**，不改变布局尺寸（用 `drawBehind`，不用 border 修饰符叠加 padding）。
- 圆角半径不存在中间值：不允许 4dp、8dp、12dp、16dp、28dp。
- 卡片不使用描边与阴影同时存在：`outlined` 变体只有 1dp 线，`flat` 变体只有底色。
- **描边宽度是 4dp 网格的唯一例外**：1 / 2 / 3dp 是视觉重量而非布局尺寸，不参与网格计算。

## 六、动效

### （一）时长

| Token | 值 | 用途 |
|---|---|---|
| `motion.instant` | 100ms | 按压反馈、图标切换 |
| `motion.fast` | 150ms | 位移 ≤ 8dp、开关滑块、勾选 |
| `motion.normal` | 250ms | 位移 ≤ 24dp、展开收起、淡入淡出 |
| `motion.slow` | 350ms | 跨区块迁移、磁贴翻转 |
| `motion.page` | 500ms | 页面切换、全出血横滑 |

### （二）缓动

| Token | 曲线 | 用途 |
|---|---|---|
| `easing.standard` | `cubic-bezier(0.2, 0, 0, 1)` | 默认。快出慢入，干脆无回弹 |
| `easing.decelerate` | `cubic-bezier(0, 0, 0, 1)` | 元素进场 |
| `easing.accelerate` | `cubic-bezier(0.3, 0, 1, 1)` | 元素退场 |

### （三）白名单

只允许以下五类动画，其余一律视为违规：

1. **位移** —— 距离 ≤ 24dp（跨屏切换除外），沿主轴，不斜向飞入。
2. **透明度** —— 0↔1，不与位移同时超过 24dp。
3. **色块揭示（reveal）** —— 用 `clipRect` 沿主轴擦出，Metro 的招牌。只用于磁贴与页面切换。
4. **磁贴翻转（flip）** —— 仅 `OmTile` 可用，Y 轴 180°，背面必须是信息而非装饰；两段各 175ms。
5. **颜色过渡** —— 明度或 accent 变化，150ms。

### （四）禁止

- 弹簧、回弹、overshoot（`spring()` 默认参数即违规）
- 阴影扩散、elevation 过渡
- 视差、3D 透视（磁贴翻转除外）
- 无限循环动画（除 indeterminate 进度；且必须是硬边扫描，不是渐隐拖尾）
- 列表进场逐项错峰的间隔不得超过 40ms，且最多 6 项

### （五）距离—时长规则

| 位移距离 | 时长 |
|---|---|
| ≤ 8dp | `fast` (150ms) |
| ≤ 24dp | `normal` (250ms) |
| 跨区块 / 跨屏 | `slow` (350ms) 或 `page` (500ms) |

## 七、交互与触感

### （一）触摸目标

- 最小 `48 × 48dp`，与视觉尺寸解耦（视觉 24dp 的图标按钮，点击区仍为 48dp）。
- 相邻可点元素的间隙 ≥ `space.1`（4dp）；列表中整行可点时以行为单位。
- **唯一例外**：高度 ≤ 32dp 的标签（`OmTag`）内的次级操作（删除）允许 28dp 命中区 —— 标签本身只有 28dp 高，内部控件不可能超过它。主操作（整块标签）仍按整块高度可点。

### （二）按压反馈

**不使用圆形水波纹（ripple）** —— 那是 Material 的语言，会立刻带偏整体气质。改用 `OmIndication`：

- 被按下的色块**明度下沉一档**（如 `neutral.100` → `neutral.200`），`motion.instant` 内完成。
- 若元素有描边，描边同时加深一档。
- 不做缩放、不做位移、不做水波扩散。
- 该反馈由 `omui-core` 的 `Modifier.omClickable` 统一实现（绘制阶段叠加 8% 黑 / 10% 白），所有可点组件必须使用它。刻意不走 Compose 的 `Indication` 接口——那套 API 已废弃，且需要把主题色塞进非组合上下文。

### （三）焦点态（键盘 / DPAD / 遥控）

- `2dp` accent 描边，绘制在元素外侧 2dp（不影响布局）。
- 焦点环与按压态可叠加，此时描边改为 `stroke.emphasis` + accent。
- 所有可交互组件必须实现，且顺序与视觉顺序一致。

### （四）选中态

| 场景 | 表现 |
|---|---|
| Pivot / Tab | 3dp accent 下划线，长度等于文字宽度（不是容器宽度） |
| 底部导航 | 3dp accent 顶部条 + 填充图标 |
| 列表选择 | 整行 `accentQuiet` 底色 + 左侧 3dp accent 竖条 |
| 磁贴选中 | 外扩 2dp accent 描边，不做缩放 |

### （五）触觉

只在这三处使用触觉反馈：长按进入选择、磁贴翻转完成、拖拽越过阈值。使用平台默认 `HapticFeedback`，不自造振动曲线。

## 八、图标

- 画布 24dp，内容区 20dp（四周留 2dp 安全边）。
- 线性图标 `stroke = 1.5dp`，**方头端点（butt cap）、直角拐角（miter join）**。
- 填充图标只用于「选中」状态，与线性版本共用同一几何。
- 图标与文本并排时，图标垂直居中于文本的**首行**，不居中于整个多行文本块。
- 库自带图标集（`omui-icons`）独立成模块，不依赖 `material-icons-extended`。

## 九、无障碍与字号适配

### （一）对比度

- 正文与 18sp 以下文本：≥ 4.5:1
- 24sp 以上或 19sp 以上加粗：≥ 3:1
- 控件边界与焦点环：≥ 3:1
- 所有色对在构建期由单元测试遍历校验（含 Spectrum 全部 8×2 组）。

### （二）三条不变量（对 UI 库是硬性 API 约束）

1. **承载文字的容器永不写死高度** —— 高度由内容决定，最小高度用 `heightIn(min = …)`。
2. **与文字并排的图标、内边距随字号等比缩放**，并设上限（`maxFactor ≈ 1.4`），元素明显变大但不失控。
3. **横向并排元素在字号缩放 > 1.3 时改为纵向堆叠**。

推论：库**不提供任何写死高度的组件**。Material 的 `TopAppBar`（64dp）、`NavigationBar`（80dp）这类做法不采用。

### （三）Display 字号的降级

`display.xl`（64sp）在 `fontScale > 1.3` 时自动降为 `display.l`，`display.l` 降为 `display.m`。巨字是风格标识，但不能挤爆屏幕。降级只作用于 Display 段，UI 段按比例放大。

### （四）RTL

- 所有「左对齐」实现为 `start` 对齐，所有「左侧竖条/指示条」实现为 `start` 侧。
- 位移方向随布局方向镜像；磁贴翻转不受影响。

## 十、设计评审清单

新增或修改任何组件前，逐条核对：

- [ ] 所有尺寸是 4dp 的整数倍？
- [ ] 圆角为 0（或属于允许的语义圆）？
- [ ] 没有阴影、渐变、模糊、半透明叠加？
- [ ] 颜色只来自语义别名（没有直接用 `neutral.xxx`）？
- [ ] 只有一个 accent 色相？
- [ ] 字号只取自字阶表，同屏不超过 4 级？
- [ ] 动效属于白名单，时长与距离匹配？
- [ ] 按压反馈是明度下沉而非 ripple？
- [ ] 焦点态存在且可见？
- [ ] 触摸目标 ≥ 48dp？
- [ ] 高度由内容决定，大字号下不裁切？
- [ ] RTL 下对齐与位移正确镜像？
- [ ] 两套主题下对比度均达标？
